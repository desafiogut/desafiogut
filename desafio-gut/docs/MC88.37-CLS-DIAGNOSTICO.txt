CAUSA RAIZ — App.jsx:78-83
================================================================================
    function DashboardOuCorporativo() {
      const { tipoUsuario, tipoCarregando, isConnected } = useAppContext();
      if (isConnected && tipoCarregando) return null;      // ← AQUI
      if (tipoUsuario === "corporativo") return <Navigate to="/corporativo" replace />;

Cronologia que o produz:
  1. Arranque: o Privy ainda não restaurou a sessão → `isConnected` é FALSE.
     A guarda não dispara e o `<Dashboard />` é pintado normalmente (1724 ms).
  2. ~4,3 s: o Privy conclui o restauro → `isConnected` passa a TRUE. Nesse
     instante o `authToken` existe e `AppContext.jsx:350` liga
     `setTipoCarregando(true)` para ir buscar as cotas.
  3. As duas condições ficam verdadeiras ao mesmo tempo → `return null` →
     o `<Outlet />` fica vazio. O `<Layout>` (e portanto o rodapé) mantém-se,
     e é por isso que o rodapé colapsa para altura 0 em vez de desaparecer.
  4. ~5,5 s: as cotas respondem, `tipoCarregando` volta a false, o Dashboard
     remonta. Segunda deslocação.

NÃO é o `<Suspense>`: o seu fallback é o `RouteFallback` ("⏳ Carregando…"), e
esse texto NUNCA aparece nas amostras. O rodapé também continua montado, o que
exclui a fronteira de Suspense (ela substituiria o Layout inteiro).


A GUARDA NÃO CUMPRE O QUE PRETENDIA
================================================================================
O comentário em `AppContext.jsx:252` declara a intenção:

    "tipoCarregando evita redirect prematuro"

Evitar um REDIRECT prematuro. Não apagar a página. O `return null` é um efeito
colateral da forma como foi escrito, não o objetivo.

E a proteção que aparenta dar já não existe na prática: o Dashboard comum JÁ é
mostrado durante os primeiros ~4,3 s (antes de `isConnected` virar). Apagá-lo
depois disso não impede nada — só acrescenta um ecrã em branco.

Há ainda uma segunda camada que trata o redirect: `AppContext.jsx:409-424` já
faz `if (tipoCarregando) return; if (tipoUsuario !== "corporativo") return;`
antes de navegar. O caso corporativo continua coberto.


HIPÓTESE ADICIONAL — O LCP DE ~5,7 s PODE SER O MESMO DEFEITO
================================================================================
O MC88.36 mediu LCP de 5720/5872 ms na baseline, com o alvo a ser o vídeo do
carrossel, e classificou-o como pendência de produto.

Os tempos coincidem com o fim deste blank. Se o Dashboard desmonta aos 4,3 s e
remonta aos 5,5 s, o carrossel é REMONTADO — e o LCP passa a ser contado a
partir da segunda pintura, não da primeira.

A verificar depois da correção. Não é afirmação, é hipótese.


CORREÇÃO PROPOSTA (S1)
================================================================================
Nenhum dos casos A–D do plano se aplica (não há espaço a reservar). A correção
é deixar de devolver `null` e passar a adiar apenas o REDIRECT, que era a
intenção declarada:

    if (tipoUsuario === "corporativo" && !tipoCarregando)
      return <Navigate to="/corporativo" replace />;
    return <Dashboard />;

Durante a deteção mostra-se o Dashboard — exatamente o que já acontecia nos
4,3 s anteriores — e o redirect continua a esperar por `tipoCarregando`.
