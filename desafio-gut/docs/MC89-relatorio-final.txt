################################################################################
1. RESUMO EXECUTIVO
################################################################################

O DesafioGUT é uma plataforma de leilão "menor lance único" com liquidação
on-chain, frontend React/Vite empacotado como app Android (Capacitor), backend em
Netlify Functions, persistência em Supabase e pagamentos via Mercado Pago/PIX.

ESTADO GERAL: **em produção na Ethereum mainnet**, com o app móvel empacotado e
assinado, campanhas de divulgação em execução automática, e a postura de segurança
recém-auditada e corrigida. Restam pendências operacionais — nenhuma delas de
arquitetura — concentradas em quatro frentes: allowlist do Privy para o WebView,
fila do Supabase, migração da assinatura para KMS, e o upload na Play Store.

PRINCIPAIS ENTREGÁVEIS DA JORNADA
  • Contrato LeilaoGUT vivo na Ethereum mainnet (marco MC60, 2026-07-09), com
    coordenação por EOA e assinatura local-key — sem ERC-4337, sem bundler.
  • Migração completa de Netlify Blobs para Supabase PostgreSQL, com RLS
    default-deny em 100% das tabelas (MC32 → MC38).
  • Blindagem anti-bot dos lances por Compromisso Cego + Key-Per-Bid (MC28.1).
  • Frontend unificado sob um único sistema de vidro (.gut-glass-standard) na
    paleta oficial navy #050818 + laranja #ff6b35.
  • App Android empacotado: AAB assinado de 34.344.316 bytes (~32,7 MB).
  • Performance do WebView reconstruída: 17,5 → 59,6 fps; JS do gate de
    consentimento de 4.002 KB → 360,5 KB; LCP de 2.220 ms → 748 ms (mediana).
  • Automação diária de divulgação em PythonAnywhere: WhatsApp concluído
    (198/198), e-mail em curso (400/1623 na última auditoria).
  • Auditoria de segurança completa (15 achados) com 13 fechados em código.
  • Suíte de testes que cresceu de 27 (MC28.1) para 209 casos, verde, sem nenhum
    teste silenciado.

3.1 — ABANDONO DO BICONOMY / ERC-4337 (MC30.2 → MC56)
     Trajetória completa: chave bruta → Defender Relay (MC30.1) → Defender entra em
     sunset → Biconomy ERC-4337 + KMS (MC30.2.1) → o bundler partilhado da Biconomy
     é desativado (MC52.1) → tentativas de recuperação (trocar URL, migrar para
     Pimlico, script local com KMS) → REDEPLOY do contrato com uma EOA simples como
     `coordenacao()` e backend em `local-key` (MC56). Consequência arquitetural
     permanente: menos superfície, menos dependências externas — exatamente a causa
     da falha original. O preço é que a chave volta a viver numa env var, o que
     mantém a migração para KMS como pendência aberta.

3.2 — MIGRAÇÃO PROGRESSIVA BLOBS → SUPABASE (MC32 → MC38)
     Padrão aplicado três vezes, sempre igual: adapter atrás de fachada → escrita
     só-Supabase (nunca dual-write) → fallback de LEITURA transitório → migração de
     dados validada byte-fiel → remoção do fallback só depois de janela de
     observação. Nenhum DROP, nenhum Blob apagado (R13, cold backup).

3.3 — REFUTAÇÃO DE PREMISSAS (padrão recorrente, não incidente isolado)
     Vários MCs entregaram o seu valor ao provar que o enunciado estava errado:
       · MC26    — "apenas ComfyUI/Nanobanana" é inexequível para vídeo.

4. LIÇÕES APRENDIDAS
################################################################################

L1 — MEDIR SEMPRE NO APARELHO. Emulação e DevTools do desktop não reproduzem o
     WebView Android. O caminho que funciona: `adb forward tcp:9333
     localabstract:webview_devtools_remote_<pid>` + CDP por WebSocket nativo do
     Node. E manter a tela acesa (`adb shell svc power stayon usb`): com a tela
     apagada o requestAnimationFrame suspende e a medição sai corrompida.

L2 — O CUSTO DO backdrop-filter VEM DO NÚMERO DE CAMADAS, NÃO DO RAIO. Cada
     elemento com a propriedade força um read-back do backdrop na GPU. Neste
     aparelho: 1 camada ≈ 1-7 fps; 11 camadas ≈ 40 fps. Onze camadas com blur de
     0px ainda custavam 29 fps. Reduzir o blur é quase inútil; reduzir a
     QUANTIDADE de elementos é o que paga.

L3 — VITE 8 (ROLLDOWN) IGNORA manualChunks. Um chunk de 0,2 KB para o React é o
     sinal de que o agrupamento não aconteceu. Usar `advancedChunks`.

L4 — A ORDEM DOS GRUPOS EM advancedChunks IMPORTA. Um pacote do caminho crítico
     pode ser acorrentado a um chunk pesado e arrastá-lo de volta ao arranque.

L5 — LAZY-LOAD SÓ FUNCIONA SE TODO O CAMINHO ESTÁTICO FOR CORTADO. Um único
     import estático (AppContext → @privy-io) anula o esforço inteiro. E `import()`
     para prefetch também AVALIA o módulo; para só descarregar, `<link rel="prefetch">`.

L6 — AO TORNAR TELEMETRIA LAZY, SEPARAR SUBSCRIÇÃO DE ENVIO. Os Core Web Vitals
     têm de ser subscritos cedo ou perdem-se; o SDK que os recebe pode chegar
     depois. Uma fila em memória preserva a observabilidade sem pagar o arranque.

L7 — UMA CONFIGURAÇÃO QUE NEGA OS DEFAULTS SEGUROS DE UM SDK É UM ALARME, NÃO UMA
     PREFERÊNCIA. E taxa de amostragem 0 não significa custo 0 — verificar no
     perfil de CPU o que continua a correr.

L8 — VALIDAR "ESTÁ LIVE?" RELENDO A PRODUÇÃO, não confiando no último deploy
     próprio. Deploy Netlify é atómico: se um asset é antigo, TODO o deploy é de
     outra linhagem. Confirmar lendo o BUNDLE JS live.

L9 — REPRODUCTION-FIRST. Vários MCs entregaram o seu valor ao refutar a própria
     premissa. Medir antes de opinar; declarar o veredito honesto mesmo quando o
     comando pede o contrário (MC59.2 recusou declarar "mainnet liberada";
     MC39.22.1 reportou +78 LOC onde o plano prometia −679).

L10 — BOULDER LOOP FUNCIONA. Máximo 3 iterações por segmento; parar e reportar.
     O MC80.3 parou após falhas repetidas no Comfy Cloud em vez de queimar o
     orçamento autorizado — custo final ≈ US$0.

L11 — MC DE DIAGNÓSTICO NÃO EXECUTA CÓDIGO. O MC82 teve de reverter três ações
     aplicadas fora de escopo. O entregável de um MC de diagnóstico é o documento.

L12 — VERIFICAR A CREDENCIAL PELO CONTEÚDO, NÃO PELO RÓTULO. No MC33.1 as chaves
     Supabase estavam trocadas: a rotulada "service_role" tinha `role:anon`. Um
     decode do JWT antes de usar evitou uma falha inteira de fase.

L13 — FERRAMENTA DE DIAGNÓSTICO PODE MENTIR POR OMISSÃO. `ffprobe -show_streams`
     não revela alfa em VP9/WebM; é preciso `-show_entries stream_tags`. E o cache
     do Graphify pode estar velho — o MC35 recusou-se a citá-lo por isso.

L14 — UM GATE DE ROTA SEM ATUALIZAR OS LINKS É UMA REGRESSÃO. O MC39.4 documentou,
     por auto-crítica, que o bug que estava a corrigir tinha sido introduzido pelo
     próprio MC39.3.1.
