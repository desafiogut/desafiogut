--------------------------------------------------------------------------------
1 · O QUE O PLANO PREVIA E POR QUE NÃO BASTAVA
--------------------------------------------------------------------------------
O plano dizia: mover o <PrivyProvider> para um PrivyRoot.jsx lazy e envolver com
Suspense. Duas descobertas obrigaram a ir mais fundo:

DESCOBERTA 1 — o chunk vinha por outro caminho
  `AppContext.jsx` importa `@privy-io/react-auth` estaticamente, e `App.jsx`
  importa o `AppProvider`. Portanto, mesmo adiando o provider, bastava o App
  entrar no arranque para o chunk `privy` vir junto.
  → Solução: o PrivyRoot passou a carregar o <App/> INTEIRO, e o gate LGPD saiu
    do App.jsx para um Boot.jsx leve, que só importa TermosConsentimento e
    BackgroundCanvas.

DESCOBERTA 2 — bug de chunking pré-existente (o achado principal)
  O `react-*.js` tinha 0,2 KB. Inspecionado, era apenas um shim:
      import{cn as t}from"./privy-*.js"; e.createRoot=...
  Ou seja: o React e o React-DOM estavam DENTRO do chunk `privy`. Qualquer ecrã
  da app — inclusive o gate — tinha de descarregar 2.745 KB só para ter React.

  Diagnóstico: o `manualChunks` do vite.config.js estava a ser SILENCIOSAMENTE
  IGNORADO pelo Rolldown (bundler do Vite 8). Confirmado por log: a função
  recebia os ids do React (`node_modules/react-dom/cjs/...`) e devolvia "react",
  mas o Rolldown mantinha-os no chunk `privy`. Uma tentativa de corrigir a
  normalização dos ids (prefixo "\0" do plugin CommonJS) produziu hashes de
  build IDÊNTICOS — prova de que o problema não era o matcher, era o
  `manualChunks` não ser honrado.
  → Solução: migrar para `advancedChunks`, a API nativa do Rolldown.

  ⚠️ A ORDEM DOS GRUPOS IMPORTA. Com `privy` antes de `motion`, o chunk do
     framer-motion (usado pelo gate via Modal e BackgroundCanvas) ficava com
     `import{cn,sn}from"./privy-*.js"` e arrastava os 2.618 KB de volta para o
     arranque. Pondo `motion` ANTES de `privy`, a corrente quebra.

  ⚠️ Uma tentativa de grupo `vendor` catch-all PIOROU (arranque subiu para
     5.117 KB, porque o vendor de 1.919 KB passou a ser carregado no boot).
     Foi revertida.

LIÇÕES QUE ESTE MC DEIXA
  1. Em Vite 8 / Rolldown, `manualChunks` pode ser silenciosamente ignorado.
     Verificar SEMPRE o tamanho real dos chunks: um chunk de 0,2 KB para o React
     é sinal de que o agrupamento não aconteceu. Usar `advancedChunks`.
  2. A ordem dos grupos de chunking é significativa: um pacote do caminho
     crítico (framer-motion) pode ficar acorrentado a um chunk pesado e
     arrastá-lo de volta ao arranque.
  3. `import()` para prefetch também AVALIA o módulo. Para só descarregar,
     usar <link rel="prefetch">.
  4. Lazy-load só funciona se TODO o caminho estático até ao módulo for cortado.
     Um único import estático (AppContext → @privy-io) anula o esforço.
