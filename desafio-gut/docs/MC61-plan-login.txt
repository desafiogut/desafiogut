0. RESUMO EXECUTIVO
--------------------------------------------------------------------------------
O objetivo (tela de login pública só com Google) é atingível com alterações
PONTUAIS em 2 arquivos. O diagnóstico, porém, revelou um ponto crítico que o
plano original não previa: a palavra "email" tem DOIS consumidores independentes
no frontend, e um deles (o login CORPORATIVO de lojistas) NÃO é o modal público.

  • "apple" → configurado em loginMethods, mas DESABILITADO no painel Privy
    (CLAUDE.md). É config MORTA — remover é seguro e puramente cosmético.
  • "email" (modal público) → aparece no modal geral de login. ALVO da remoção.
  • "email" (corporativo) → SejaNossoParceiro.jsx usa useLoginWithEmail (OTP
    headless, sendCode/loginWithCode). Remover "email" GLOBALMENTE muito
    provavelmente QUEBRA o cadastro/login de lojistas.

Por isso o escopo aprovado é a OPÇÃO A: manter "email" habilitado no config
global (para o OTP corporativo continuar funcionando) e restringir o MODAL
PÚBLICO a Google via login({ loginMethods: ["google"] }).

2. DIAGNÓSTICO DETALHADO (SEGMENTO 1) — arquivo:linha · descrição · impacto
--------------------------------------------------------------------------------
[D1] main.jsx:258  loginMethods: ["google","email","apple"]
     Descrição: define os métodos do modal de login público.
     Impacto da remoção de "apple": NENHUM funcional (apple já desabilitado no
       painel Privy → botão não aparece hoje). Limpeza de config.
     Impacto da remoção de "email" AQUI (global): removeria o email do modal
       público E, potencialmente, desabilitaria useLoginWithEmail (corporativo).
       → por isso NÃO removemos "email" do global na Opção A.

[D2] SejaNossoParceiro.jsx:73  useLoginWithEmail()
     Descrição: login/cadastro corporativo por OTP de email (headless, sem modal).
     Impacto: se "email" sair do config global, sendCode/loginWithCode podem
       falhar ("email login not enabled") → cadastro e login de LOJISTAS quebram.
     Severidade: ALTA. É a dependência indireta central do MC61.
     Mitigação (Opção A): manter "email" no config global; corporativo intacto.

[D3] AppContext.jsx:746-768  abrirModal → login()
     Descrição: único ponto que abre o modal público. Hoje sem loginMethods →
       herda o global (mostra google+email+apple).
     Impacto: é o lugar CERTO para restringir o modal público a Google sem
       tocar no corporativo.

[D4] Painel Privy (Dashboard) — fora do código
     Estado: Google ATIVO, Email ATIVO, Apple DESATIVADO (CLAUDE.md).
     Observação: loginMethods do SDK é um SUBCONJUNTO do que o painel habilita;
       não é possível "ativar" pelo array algo desligado no painel. Logo "apple"
       no array é inerte. Email deve PERMANECER ativo no painel (corporativo).

Avaliação de impacto em usuários existentes:
     O Privy unifica identidades por conta. Restringir o modal a Google NÃO
     apaga identidades email/apple já vinculadas. Usuários que hoje entram por
     email no modal público passariam a ver só Google — se a conta deles não tem
     Google vinculado, precisariam usar Google. (Ponto a confirmar com o operador
     se houver base relevante de usuários público-email; corporativo é preservado.)

🔧 ALTERAÇÃO 1 — main.jsx (config do Privy): remover só "apple"
   Arquivo: frontend/src/main.jsx
   Linha 257 (comentário) e 258 (array).
   DE:   // ── Métodos de login: Google, E-mail, Apple ─────────
         loginMethods: ["google", "email", "apple"],
   PARA: // ── Métodos de login: Google (modal público) + E-mail (OTP corporativo) ──
         loginMethods: ["google", "email"],
   Motivo: "apple" é config morta (painel desligado); "email" fica para o OTP
           corporativo (useLoginWithEmail). ZERO impacto funcional.

🔧 ALTERAÇÃO 2 — AppContext.jsx (restringir o modal PÚBLICO a Google)
   Arquivo: frontend/src/context/AppContext.jsx  (função abrirModal, ~746-768)
   Ideia: quando o chamador NÃO passa loginMethods, abrir o modal só com Google.
          Preservar overrides explícitos (prefill/loginMethods) para não quebrar
          nenhum caller futuro nem o corporativo.
   DE (linha 767-768):
         const loginOpts = opts && (opts.prefill || opts.loginMethods) ? opts : undefined;
         const result = loginOpts ? login(loginOpts) : login();
   PARA (equivalente, com default Google-only):
         const base = opts && (opts.prefill || opts.loginMethods) ? { ...opts } : {};
         if (!base.loginMethods) base.loginMethods = ["google"]; // modal público só Google
         const result = login(base);
   Motivo: todo o login público passa por aqui; 1 mudança cobre todas as telas.
           Não toca no fluxo corporativo (que usa sendCode direto, sem abrirModal).

🔧 ALTERAÇÃO 3 — Painel Privy (Dashboard) — SEM código
   Ação: confirmar Google=ATIVO, Email=ATIVO (necessário p/ OTP corporativo),
         Apple=DESATIVADO (já está). Nenhuma mudança esperada; só verificação.
   Responsável: operador (o agente não acessa o painel).

🔧 ALTERAÇÃO 4 — Testes
