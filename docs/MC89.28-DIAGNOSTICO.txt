0.2 — CARDS-ZERO: A REGRA JÁ EXISTE E JÁ ESTÁ APLICADA
--------------------------------------------------------------------------------
`_ui.jsx:48` define, desde o MC89.1:

    // REGRA R-UI-1: número indisponível mostra-se como "—", NUNCA como 0.
    export function ouTraco(valor, formatar = (v) => String(v)) {
      return valor === null || valor === undefined ? "—" : formatar(valor);
    }

É exactamente a convenção que o enunciado propõe em 2.1 (null/undefined → "—";
0 → "0"). Está aplicada em 20 sítios: VisaoGeral (11), GestaoFinanceira (5),
Operacoes (1, cobre as 4 métricas da fila), GestaoUsuarios (1), LogsAuditoria (1).

O backend coopera: `admin-series.mjs:191` devolve `totalCreditos: creditos ?
creditos.length : null` e as séries diárias usam `|| null` — nunca preenche com
zero. O comentário na linha 79 di-lo por extenso.

⇒ Não existe, no frontend, um card que mostre 0 por falta de dados.
   O Segmento 2 tal como redigido não tem trabalho a fazer.

>>> MAS: DEFEITO REAL ENCONTRADO (mais fundo que o enunciado imaginava) <<<

`netlify/functions/_lib/admin-comandos.mjs:82` — `estadoFila()`:

    const { data, error, count } = await sb.from("fila_tarefas")
      .select("*", { count: "exact" })
      .order("criado_em", { ascending: false })
      .limit(limite);              // limite = 30 (admin-queue.mjs:28)
    ...
    for (const t of linhas) porStatus[t.status] = (porStatus[t.status]||0)+1;
    return {
      total:      count ?? linhas.length,   // ← contagem GLOBAL (exact)
      pendentes:  porStatus.pending || 0,   // ← contada só nas 30 mais RECENTES
      concluidas: porStatus.done    || 0,
      falhas:     porStatus.failed  || 0,
      linhas,
    };

`total` é global; o desdobramento por status é calculado sobre uma janela de 30
linhas. Com a fila acima de 30 tarefas, o painel pode mostrar
"Total 500 · Pendentes 0" enquanto existem pendentes fora da janela.

Um zero falso é pior que um "—": afirma que a fila está limpa. É precisamente a
classe de defeito que o R-UI-1 existe para evitar — mas está do lado do servidor,
onde o `ouTraco` não chega.

VERIFICAÇÃO CONTRA A BASE (não contra a minha suposição):
    select status, count(*) from fila_tarefas group by status;
    →  done: 5

Hoje a fila tem 5 linhas, logo a janela de 30 cobre tudo e os números estão
correctos. O defeito é LATENTE, não activo. Não inventei um sintoma: digo que
não há sintoma hoje e que ele aparece assim que a fila passar de 30.

`estadoFila` tem um único consumidor (admin-queue.mjs:30), logo a correcção é
contida. O `metricas_fila` do chatbot vem de outro caminho (admin-metricas).
