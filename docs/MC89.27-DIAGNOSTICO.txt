0.4 — POR QUE FALTAM ESSAS VARIÁVEIS: A CAUSA-RAIZ
--------------------------------------------------------------------------------
Existem dois caminhos de build, e eles produzem bundles DIFERENTES:

  (A) npm run build          = "vite build"
      → Vite lê os ficheiros .env do DISCO.
      → desafio-gut/frontend/.env contém APENAS:
            VITE_CONTRATO_MAINNET=0x0052477A8CA81BCAF4a60e21e635F9e00a5d16cd
            VITE_NETWORK_STAGE=mainnet
      → Não há VITE_CHAIN_ID nem VITE_CONTRATO_SEPOLIA em lado nenhum do disco.
      → RESULTADO: bundle Sepolia-por-omissão e sem contrato.  ← É ESTE O APK ATUAL

  (B) npm run build:apk      = netlify build --context production
                               && npm run validar:dist && npx cap sync android
      → O Netlify injecta o env do contexto de produção, que está CORRETO:
            VITE_CHAIN_ID         = 1
            VITE_CONTRATO_SEPOLIA = 0x0052477A8CA81BCAF4a60e21e635F9e00a5d16cd
            VITE_ALCHEMY_URL      = https://eth-mainnet.g.alchemy.com/...
            VITE_EXPLORER_URL     = https://etherscan.io
            VITE_NETWORK_STAGE    = mainnet
      → O env do contexto tem precedência sobre os .env do disco.
      → RESULTADO: bundle mainnet coerente, e o validador deixa passar.

O MC89.26 foi compilado pelo caminho (A). É essa, e apenas essa, a origem.

--------------------------------------------------------------------------------
0.5 — POR QUE A LIMPEZA MANUAL DO BUNDLE NÃO RESOLVEU
--------------------------------------------------------------------------------
A substituição manual no dist trocou ocorrências do endereço de contrato.
Mas o defeito não era um endereço errado presente — era duas variáveis
AUSENTES. Não se corrige uma ausência com um "find & replace": não havia
`VITE_CHAIN_ID:` no ficheiro para substituir. O default 11155111 vive em
network.js e só é evitado se a variável EXISTIR no momento do build.

Lição: editar o artefacto compilado nunca podia funcionar aqui. A configuração
de rede é resolvida em tempo de build, não em tempo de execução.

--------------------------------------------------------------------------------
0.6 — GRAVIDADE REAL (maior do que "uma mensagem incómoda")
--------------------------------------------------------------------------------
O aviso é cosmético; o estado que ele denuncia não é. No APK atual:
  • CONTRATO = ""  → leitura de saldo de senhas e envio de lance falham.
  • Sem VITE_ALCHEMY_URL → sem RPC de mainnet.
  • É a mesma configuração que causou o MC88.24 ("o PIX debitou e a senha não
    creditou"), que custou um MC inteiro a diagnosticar.

Este componente (AvisoRede, MC88.25) foi criado precisamente para tornar esse
estado visível em dois minutos em vez de um MC. Cumpriu a sua função.

⚠️ CONCLUSÃO DE DESENHO: silenciar a mensagem — mexer em AvisoRede.jsx, no
default de network.js, ou fazer network.js aceitar VITE_CONTRATO_MAINNET —
seria a correção ERRADA. Apagaria o alarme e deixaria o defeito. A correção
certa é recompilar pelo caminho (B); a mensagem desaparece por consequência,
que é exatamente como este componente foi desenhado para se comportar.
