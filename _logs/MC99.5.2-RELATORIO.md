## 1. Sumário executivo

O SSRF de `img-proxy.mjs` foi **explorado antes de corrigido**, e a correcção foi **iterada três

## 2. SSRF — exploração (HARD GATE 1)

PoC contra o **código real** (função exportada), reproduzindo a cadeia das linhas 78-80:

```
ANTES:  BLOQUEADO 127.0.0.1 | localhost | 169.254.169.254
        EXPLORA   [::1]  [::ffff:127.0.0.1]  [fc00::1]  [fd00::1]
        OK-LEGIT  2/2  (i.imgur.com, exemplo.com)
```

Causa: `new URL("http://[::1]/").hostname` devolve `"[::1]"` **com brackets**; `isBlockedIp` só
conhecia a forma sem eles, e `u.hostname.includes(":")` marcava-o como IP literal **saltando a
verificação DNS**. Duas guardas caíam pela mesma causa.

## 4. Gate legal — só um botão, sem resumo (DECISÃO DO OPERADOR, R18)

**Decisão:** «no gate, não precisa de resumo, somente um botão para expandir».
**Implementação (Ponytail, degrau 4 — feature nativa):** `<details>`/`<summary>` — botão acessível
por teclado e leitor de ecrã, **sem `useState`, sem re-render, sem CSS de estado**. Fechado por
omissão; ao abrir, o texto é 100% visível (herança do MC99.5.1). **Os 4 aceites ficam FORA do
`<details>`** — visíveis e clicáveis com o botão fechado, que é o que a validade do consentimento
exige.

⚠️ **Observação do HERMES (a decisão é do operador):** o MC99.5.1 existiu porque o texto estava
ilegível (2,4%); agora está a **um clique**. Com um botão bem sinalizado é defensável e é o que
foi pedido — mas é a diferença entre «o utilizador **podia** ler» e «o utilizador **viu**». Fica
registado como decisão, não como equivalência.

## 8. Lições

1. **Uma correcção de segurança sem caça adversarial é uma correcção com sorte.** Iterei 3 vezes:
   cada versão parecia completa, e **cada uma tinha um buraco** — o 1.º achou-o o PoC re-corrido,
   os outros 3 achou-os a caça de 17 formas. *O que transformou «parece corrigido» em «está
   corrigido» não foi escrever melhor o fix: foi tentar parti-lo.*
2. **O nome é o contrato.** `isBlockedHostname` recebe o `hostname` **já normalizado pelo URL** —
   e eu testei a forma escrita à mão. O teste falhou, o código estava certo, e ler a falha exigiu
   perceber **quem normaliza o quê**: o URL normaliza, a função recebe. *Testar o valor que eu
   imaginei em vez do que o sistema entrega dá RED no sítio errado.*
3. **Nem todo o payload suspeito é um payload.** Dois dos «17» eram userinfo, não SSRF. Uma caça
   que não distingue os dois **acusa o código pelo erro da lista** — e um falso positivo num
   relatório de segurança custa tanto como um falso negativo.

## 9. ⚠️ ADENDA OBRIGATÓRIA — O VALIDADOR REFUTOU-ME, E EU TINHA ESCRITO «0 BYPASS»

Na §3 escrevi «3.ª iteração → 0/17, nada aberto» e fiz commit disso. **Estava errado.**
O validador independente encontrou **≥15 payloads IPv6 que passavam** (e 6 classes também em
produção):

```
fe90::1 fea0::1 feb0::1 febf::1     PASSAVAM  <- cauda de fe80::/10 (eu testei o literal "fe80")
fec0::1 fed0::1 fee0::1 feff::1     PASSAVAM  <- site-local fec0::/10, nunca coberto
::ffff:0:0:a00:1                    PASSAVA   <- mapeado com 3 grupos (a minha regex exigia 2)
::7f00:1  ::a00:1                   PASSAVAM  <- IPv4-compatível
64:ff9b:1::7f00:1                   PASSAVA   <- variante do NAT64
```

### 9.1 O erro de fundo não era faltar um caso — era ESTAR A ENUMERAR

Três iterações, e cada uma parecia completa. **Uma guarda por lista de prefixos nunca fecha:**
o espaço é grande, e eu só testava as formas que me lembrava de imaginar. A correcção final
**abandona a enumeração**:

- (a) descodifica o **IPv4 embutido** de qualquer forma mapeada / 6to4 / NAT64 e reutiliza
  `isBlockedIp`;
- (b) para o resto, **allowlist de intervalo**: só `2000::/3` (unicast global) passa, **tudo o
  resto é recusado**. Loopback, link-local (`fe80::/10` **inteiro**, incl. `fe90..febf`),
  site-local (`fec0::/10`), ULA, multicast, unspecified, compatível e mapeado caem todos de uma
  vez — **com menos código do que a lista que falhava**.

### 9.2 E, ao corrigir, introduzi uma regressão GRAVE — apanhada pelos controlos POSITIVOS

A 1.ª versão do guard de intervalo não distinguiu **domínio** de **IPv6**. Como `isBlockedIp`
também é chamado com nomes de domínio (última linha de `isBlockedHostname`), o resultado foi:

```
https://i.imgur.com/foto.png    -> 403     <- o proxy de imagens recusava TODAS as imagens
```

**Quem apanhou isto não foi um teste de payload — foi o controlo POSITIVO.** Um teste que só
verifica «o malicioso é recusado» fica verde com «bloquear tudo»: foi exactamente o que o
HARD GATE 7 (teste bidireccional) existe para impedir. Se eu tivesse medido só os payloads,
teria entregue um SSRF fechado **e um proxy de imagens morto** — dois defeitos com um commit.
A correcção: `if (!h.includes(":")) return false;` — o IPv4 pontuado já saiu acima; o que chega
sem `:` é um domínio, e a um domínio não se aplica o intervalo.
