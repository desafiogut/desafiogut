## -1.4 Documentação da Frenet (lida a 2026-09-29)
**Consulta:** `POST https://api.frenet.com.br/tracking/trackinginfo` (docs.frenet.com.br/reference/trackorder).
- Autenticação: header **`token`**.
- Corpo: `ShippingServiceCode` (**obrigatório**), `TrackingNumber` (obrigatório); opcionais `InvoiceNumber`, `InvoiceSerie`, `RecipientDocument` (CPF/CNPJ), `OrderNumber`.
- Resposta: `TrackingNumber`, `TrackingUrl`, `ServiceDescrition`, `ErrorMessage`, `TrackingEvents[{EventDateTime, EventLocation, EventDescription, EventType}]`.

**Webhook «Atualização de Tracking»** (docs.frenet.com.br/docs/webhook-atualização-de-tracking):
- `POST` JSON para o nosso endpoint.
- Autenticação por **um header próprio `[TOKEN_NAME]: [TOKEN_VALUE]`**, que se define com a Frenet.
- Tem de responder **2XX em ≤ 10 s**; um 3XX conta como falha.
- Payload: `OrderId`, `ShipmentId`, `TrackingUrl`, `TrackingNumber`, `ServiceDescrition`, `TrackingEvents[{EventDateTime:"10/02/2017 16:48", EventDescription, EventLocation, EventType:"9"}]`.
- **Só o último evento vai em cada chamada.** O comportamento de reenvio não está documentado.
- **EventType:** 0 Postado · 1 Em trânsito · 2 Atrasado · 3 Devolvido · 4 Extraviado · 5 Saiu para entrega · 9 Entregue · 18 Aguardando retirada.
- Dados pessoais no payload: **não há** nome, CPF nem morada. `EventLocation` é uma cidade, e mesmo assim não se grava (DEC-102.1b-5). ⇒ a ressalva «se a Frenet expuser dados pessoais → PARAR» **não se aplica**.

## PoC (antes de tocar em código) — `scratchpad/poc-frenet.mjs`
O token é lido **só em memória** do processo (`netlify env:get` capturado) e **nunca é impresso**; qualquer eco na resposta é mascarado.

| Chamada | Resposta |
|---|---|
| token ERRADO (controlo) | 200 · `{"ErrorMessage":"cliente não escolheu um plano de pagamento…"}` |
| token real, código inexistente, SEDEX 03220 | 200 · `{"ExpectedDate":"0001-01-01T00:00:00"}` (sem erro, sem eventos) |
| token real, SEM serviço | 200 · `ErrorMessage: "ShippingServiceCode ou CarrierCode informado não foram encontrados"` |
| token real, objecto de teste da doc | 200 · sem eventos |

**Conclusões:**
- **O token autentica**: o controlo com token errado dá outra resposta.
- **A API responde 200 aos erros** e o erro vem em `ErrorMessage`, por isso o adaptador tem de o ler.
- **Um código sem eventos não é erro.**
- **A Frenet tem planos pagos**: o custo por consulta NÃO está medido (R2).
