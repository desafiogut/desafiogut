## A3 — Causa-raiz do erro (3) — **REFUTADA** ← refutação principal

Li a biblioteca real (`@supabase/realtime-js` **2.108.2** + `@supabase/phoenix` **0.4.4**):

```

EXP1 dedupe por topic (a===b): true | getChannels().length: 1
EXP2 SINCRONO logo apos removeChannel (sem await): length = 0 | state = closed | isJoined: false
EXP2 channel(mesmo topic) devolveu o canal ANTIGO? false
EXP B (socket LIGADO) SINCRONO apos removeChannel: length = 0 | state: closed
     dedupe devolveu o antigo? false | .on() -> NAO lancou | .subscribe() -> NAO lancou
EXP D DOIS ligar() para o MESMO topic, SEM remocao: dedupe devolveu o mesmo? true
     .on() no 2.o -> THROW: cannot add `postgres_changes` callbacks for realtime:config_remota:X after `subscribe()`.
```
A dedupe **existe** e `removeChannel` **é** assíncrono — mas a conclusão do MC é falsa. Cadeia real: `removeChannel` → `unsubscribe()` → phoenix `leave()` → `if(!this.canPush()) leavePush.trigger("ok")` → `onClose` → `state = closed` + `socket.remove(this)` → `RealtimeClient._remove` filtra o array **sincronamente**; e `channel()` só reutiliza canais **não-fechados** (`if(!exists)`… na versão lida: `_remove` no `onClose`). Logo, **sem await** a remoção já retirou o canal: o reconnect recebe um canal NOVO fechado e `.on()` não lança. Medi com socket ligado e desligado — igual. **O `await` é defensivo, não é a causa-raiz.**

Causa real que **reproduzi** (com o hook do 2502ccb verbatim + biblioteca real):
```

=== ROTA /mercado: MercadoLances monta primeiro, CardLance a seguir ===
  [MercadoLances] ligou o canal, canal = true
  2.o hook LANCOU: cannot add `postgres_changes` callbacks for realtime:config_remota:recursos_app after `subscribe()`.
```
A rota `/mercado` monta `MercadoLances` **e** `CardLance`; ambos importam `useRecursosApp`, que chama `useRealtimeConfig(CHAVE_RECURSOS=...)` → **dois hooks, MESMO topic, MESMO cliente global** → a dedupe devolve o canal subscrito e o 2.º `.on()` rebenta. **O defeito real continua em produção.**

## Problemas encontrados (por gravidade)

1. **Causa-raiz de (3) errada** (A3). O `await` não corrige nada do que o comentário afirma; medido contra a biblioteca real. O erro real vem de **dois hooks para o mesmo topic no mesmo cliente** via `/mercado` → `MercadoLances` + `CardLance` → `useRecursosApp`. **Muito provavelmente o erro (3) persiste em produção.**
2. **HARD GATE 4 contornável**: `https://*.*.com`, e `*` em directivas não vigiadas (`style-src`, `font-src`), e cego a comentários.
3. **SEG1 é vacuidade real**: o mutante M6 (async + await, forma intacta) sobrevive a medir 2 clientes.
4. `.catch` do singleton: janela residual (converge para 1 na prática, mas não é garantido por desenho).
5. O mesmo defeito de contagem (`?`) aparece como "10 ocorrências" no enunciado e "9×" no comentário do teste.
6. Endurecimento ausente: `_promessa`/`canal` guardas de reentrada dependem de disciplina; `.channel()` devolve canal não-fechado, logo o padrão "um topic por hook" não é imposto.
7. `useRecursosApp` e `useRealtimeConfig` usam o mesmo tema; o fix devia ter deduplicado **por (chave, consumidor)** ou elevado o canal a um contexto.
