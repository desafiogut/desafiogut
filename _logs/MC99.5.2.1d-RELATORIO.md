# MC99.5.2.1d — PARADO A MEIO, POR INSTRUCAO DO PROPRIO MC

**Data:** 2026-09-27 · **Base:** f6b1d7a · **Estado:** INVERSÃO NO CAMINHO DNS **NÃO APLICADA**

## 1. Porque parei

O MC 99.5.2.1d traz duas ressalvas explicitas, e a segunda dispara:

- «Se a inversão quebrar algum caso legítimo, PARAR e reportar.»
- «Trade-off declarado: hosts de imagens IPv6-only deixam de funcionar. Se isto for inaceitável
   para o operador, a alternativa é uma allowlist positiva de CDNs conhecidas — PARAR e reportar
   antes de aplicar.»

**A inversão de uma linha, aplicada literalmente, PARTIU um domínio legítimo — e não um caso
exótico: `cdn.jsdelivr.net`, um CDN que a própria app usa.**

## 2. A medição (o que a inversão literal faz)

```
DEPOIS da inversão literal (results.some(r => r.address.includes(":") || isBlockedIp(...))):
  CAMINHO_DNS: maliciosos que PASSARAM: 0/3   <- FECHOU o buraco (era 3/3)
  CAMINHO_DNS: legitimos BLOQUEADOS:    1/3   <- PARTIU um CDN

cdn.jsdelivr.net -> 2606:4700::6811:d005, 2606:4700::6811:cf05, 104.17.207.5, 104.17.208.5
                    |_______ AAAA (IPv6) _______|   |______ A (IPv4 publico) ______|
```

## 3. O trade-off nao era o que eu declarara

Eu escrevi, no relatorio anterior, que o custo era «hosts de imagens IPv6-only» e classifiquei-o
de raro. **Esta medição mostra que o custo real é outro: qualquer host DUAL-STACK é bloqueado,**
porque a inversão bloqueia se QUALQUER endereco for IPv6 — e um host dual-stack tem AAAA *e* A.
Isso nao é «raro»: e a maior parte da web moderna, e inclui o CDN que a app usa.

**Segunda vez neste MC-serie que uma classificacao minha de risco estava errada** — primeiro
classifiquei de exotico um caminho com servico publico dedicado (sslip.io); agora classifiquei de
raro um custo que atinge a maioria dos hostnames. *As duas vezes o erro foi o mesmo: avaliei o
risco pelo que me lembrei de imaginar, nao pelo que fui medir.*

## 4. A alternativa que proponho (NAO aplicada — decisao do operador)

Ignorar os AAAA e validar os A; bloquear so quando NAO houver nenhum IPv4:

```js
const v4 = results.filter((r) => !r.address.includes(":"));
return v4.length === 0 || v4.some((r) => isBlockedIp(r.address));
```

| caso | resultado |
|---|---|
| `cdn.jsdelivr.net` (dual-stack) | v4 = 104.17.207.5, 104.17.208.5 -> publico -> **PASSA** |
| `2601--5efe-a9fe-a9fe.sslip.io` (so AAAA) | v4 = [] -> **403** (buraco FECHADO) |
| dominio com A privado | isBlockedIp -> **403** |
| host legitimo IPv6-ONLY | v4 = [] -> **403** (o custo real e declarado, agora corretamente) |

**Fecha o exploit e mantem os CDNs dual-stack a funcionar.** O custo fica reduzido ao que eu
tinha declarado mal — hosts IPv6-only, esses sim raros.

Alternativa do MC: allowlist positiva de CDNs conhecidas (mais restritiva e mais manutencao).

## 5. O que ESTA feito e commitado (e o que NAO esta)

NAO FEITO (por instrucao do MC):

## 7. Pendente de decisao do operador

1. Aplicar a variante **«ignorar AAAA, validar A»** (recomendada) — fecha o exploit e mantem os

2. Ou a **allowlist positiva de CDNs** (mais restritiva).
3. Ou aceitar o custo da inversao literal (bloquear todo o host dual-stack) — que, medido, e
