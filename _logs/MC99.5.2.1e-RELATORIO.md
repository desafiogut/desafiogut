## 0. Sumário executivo

**O que estava aberto.** Seis gerações de guarda foram refutadas, cada uma a fechar o ataque da
anterior e a abrir outro. A causa-raiz, identificada na 6.ª (`MC99.5.2.1d`), não era «falta um
caso»: **a guarda validava o resultado de UMA resolução de DNS e o `fetch` fazia OUTRA resolução
independente**, escolhendo livremente o endereço a que se ligava. Duas resoluções, duas escolhas,
nenhuma garantia de coincidirem — isso é **TOCTOU**, e é o que o DNS rebinding explora.

**Medido antes de tocar em nada (SEG-1, handler REAL, isco HTTP em `[::1]`):**

```
http://1-1-1-1.--1.sslip.io:<porta>/x.png   -> 200 image/png   *** ISCO SERVIDO, SSRF VIVO ***
    (A público 1.1.1.1 + AAAA ::1 — a guarda aprovou o A, o fetch ligou-se ao AAAA)
http://1-1-1-1.2601--5efe-a9fe-a9fe.sslip.io  -> 502  (passou a guarda; AAAA ISATAP -> metadata)
http://10-0-0-1.2601--5efe-a9fe-a9fe.sslip.io -> 403  (contraste: com A privado, bloqueia)
```

**A correcção (não acrescenta regras — muda ONDE a decisão acontece).** Resolve-se **uma única
vez** (a nossa); autoriza-se **cada** endereço devolvido; e a ligação passa a levar um
`undici.Agent` com `connect.lookup` próprio, chamado **no momento da ligação**, que devolve **só** o
endereço validado — ou **recusa**, e nesse caso a ligação não chega a acontecer. O `fetch` deixou de
ter resolução própria para correr. **As duas resoluções passaram a uma.**

**Estado:** corrigido e verificado localmente; **deploy e validação em produção nesta mesma
sessão**; validador adversarial independente despachado (veredicto em §5).

## 1. A mudança: validar onde a ligação acontece

### 1.1 As três peças novas em `img-proxy.mjs`

| peça | o que faz |
|---|---|
| `resolverEEscolher(nome)` | **UMA** resolução (`lookup(all:true)`); autoriza **CADA** endereço (`isBlockedIp` + IPv6 com IPv4 embutido por transição); exige **≥1 IPv4**; devolve `{bloqueado, pin}` |
| `lookupValidado(host, opts, cb)` | o `connect.lookup` do Agent: devolve `[{address: pin, family: 4}]` **ou** `Error(HOST_BLOQUEADO)` — recusa na ligação |
| `agenteValidado` | um `undici.Agent` **partilhado** com esse lookup (a decisão é por-requisição, dentro do lookup — não é preciso um agent por pedido, logo o keep-alive mantém-se) |

O handler perdeu o pré-check de DNS:

```js
if (isBlockedHostname(u.hostname)) return texto(403, "host not allowed");
const ehIpLiteral = /^\d+\.\d+\.\d+\.\d+$/.test(u.hostname) || u.hostname.includes(":");
// (já não há `if (!ehIpLiteral && await resolvesToBlocked(...)) return 403`)
const r = await fetch(u.toString(), {
  signal: ctrl.signal, redirect: "error", headers: { Accept: "image/*" },
  ...(ehIpLiteral ? {} : { dispatcher: agenteValidado }),
});
```

e o `catch` distingue a **nossa** recusa de uma falha de rede — é o que dá **403** em vez de 502:

```js
} catch (e) {
  if (erroEhHostBloqueado(e)) return texto(403, "host not allowed");   // o marcador sobe no `cause`
  return texto(502, "fetch failed");
}
```

**`isBlockedHostname` NÃO foi tocado** — a 5.ª geração (recusa de literais IPv6) continua fechada.
Literais de IP não passam pelo dispatcher (não há DNS a fazer).

### 1.2 Medições que decidiram o desenho (SEG0.1 — antes de escrever o fix)

| pergunta | resultado medido |
|---|---|
| Assinatura do `connect.lookup` no undici | recebe `options = {hints:0, all:true}` → **tem de devolver um ARRAY** `[{address, family}]`. O 1.º instrumento devolveu um escalar e deu `Invalid IP address: undefined` — foi o PRÓPRIO instrumento a mostrar o contrato |
| O **pin** funciona? | pin → `::1`, `fetch` a um NOME que não resolve para lá → **200 image/png do isco**, **1** resolução DNS |
| HTTPS/SNI sobrevivem? | `cdn.jsdelivr.net` e `i.imgur.com` por NOME com o endereço fixado → **200 image/*** (o TLS fechou com o SNI do nome) |
| O `fetch` GLOBAL do Node 24 aceita o Agent do npm? | **sim** (200 pelo lookup próprio, 1 resolução) — o dispatcher usa símbolos globais, compatível entre versões |
| O marcador de recusa sobrevive ao erro do fetch? | **sim**: `err.cause.message === "__img_proxy_host_bloqueado__"` → dá para responder 403 |

Não foi preciso acrescentar dependência nenhuma ao *código*: mas descobriu-se que `undici` era
**dependência-fantasma** (resolvia por hoisting; não estava em manifesto nenhum) — foi **declarado**
em `netlify/functions/package.json` (`^6.25.0`, instalado `6.29.0`).

## 4. Erros dos MEUS instrumentos, encontrados e corrigidos nesta geração

> O padrão do operador: os erros ficam **à vista**, corrigidos no instrumento — nunca apagados.

1. **A régua `codigo()` comia CÓDIGO real.** O stripper de comentários removia tudo a partir de `//`
   numa linha. Em `if (!/^image\//i.test(ct))` a **barra** de `\/` conta como início de comentário →
   a linha desaparecia do texto medido. Um predicado de mutação ou uma asserção sobre esse trecho
   mediria um alvo mutilado. Corrigido nos **dois** sítios (teste e mutador) excluindo `\` antes de
   `//`. *(Classe «a régua mais estreita/larga que o alvo».)*
2. **O PoC da série era o ponto cego.** `scripts/mc9952-poc-ssrf.mjs` replicava no `decidir()` a
   cadeia **antiga** («nome → PASSA»), e **por isso nunca viu o ataque prefixado** — dizia «PASSA
   (dns corre)» enquanto o ataque era real. Passa a medir `resolverEEscolher`, a mesma decisão que a
   ligação usa. Acrescentada a lista `SEXTA_GERACAO` (a que faltava).
3. **`a.b.c.d.com.br` estava na lista de «legítimos»** e o PoC acusava-o de **regressão**. Não
   resolve (NXDOMAIN) → 403 nas DUAS gerações (medido no A/B). Era a minha asserção a ser mais
   estreita que o alvo; saiu da lista e o fail-closed herdado passou a ser medido à parte.
4. **Expectativa 403 para `file:`/`gopher:`** no verificador ad-hoc: o handler recusa o **esquema**
   mais cedo, com **400**. Bloqueio igual, código diferente — a asserção é que estava errada.
5. **`undici` era dependência-fantasma.** Não é um erro de medição, mas é o mesmo padrão: algo que
   funciona por acidente do ambiente (hoisting) e quebra no ambiente a sério. Declarado.
6. **A MINHA lista de payloads era o ponto cego — outra vez.** O **validador adversarial** encontrou
   as faixas de propósito especial (§5) que a minha lista não tinha. Já não é só o PoC a replicar a
   cadeia antiga: é a cobertura a ser desenhada pelo que eu me lembrei de escrever. As faixas
   passaram a ser medidas **à vista** no instrumento de produção.

## 5. Veredicto do validador adversarial (HARD GATE 7)

**Subagente independente, em worktree próprio** (`C:/Users/Moltbot/Desktop/valida-99521e-7f3a`,
`git worktree add --detach … 33e9c80`), instruído a **TENTAR REFUTAR** — não a confirmar — com 10
vectores obrigatórios. Instrumentou o DNS por patch e os sockets por evento.

### VEREDICTO: **NÃO REFUTADO**

> «Não consegui, em nenhum dos 10 vectores, fazer o handler ligar-se a um endereço interno nem
> servir conteúdo que não viesse do endereço validado.»

**Controlo de CAPACIDADE do instrumento (é o que dá valor ao «não encontrei»):** o mesmo rig, contra
a guarda **antiga** (`df0439a`), deu **200 — SSRF VIVO** no `1-1-1-1.--1.sslip.io`; contra a nova dá
403. A instrumentação **não é cega**: vê o SSRF quando ele existe.

| vector | medição do validador |
|---|---|
| **1. novo nome prefixado** | 403 em todas as variantes (DNS do alvo confirmado antes de concluir) |
| **2. redirects** | `redirect:"error"` **lança** «unexpected redirect»; o lookup do dispatcher **não** é chamado uma 2.ª vez |
| **3. esquemas / URL** | `file:`/`gopher:`/`ftp:`/`data:`/`blob:`/`ws:` recusados antes de qualquer ligação; userinfo (`http://evil:segredo@1.1.1.1/`, `http://[::1]@1.1.1.1/`) → `hostname` é `1.1.1.1` — **não é SSRF**, classificado correctamente |
| **4. DNS rebinding** | `rbndr.us`/`1u.ms` **e um servidor DNS próprio em `127.0.0.1:53`** com respostas alternadas: o `dns.lookup` do handler usa o resolver do sistema (getaddrinfo) e **ignorou** o servidor de teste; com um shim de DNS hostil → **1 só resolução**, e o endereço devolvido ao conector é o validado |
| **5. timing / 2.ª resolução** | em **todos** os casos: `resolucoesDoGuard=1 · resolucoesDefaultDoNet=0 · chamadasAoLookupNaLigacao=1` (maiúsculas, ponto final, `%00`, `../`, keep-alive expirado, 2 pedidos seguidos) |
| **6. armadilha do `pin`** | `http://cdn.jsdelivr.net/...` → evento de socket **`connect` remoto `104.17.208.5:80`** (o endereço FIXADO, não o nome); loopback/privados/metadata directos → 403 com **0 sockets** |
| **7. controlos positivos** | **6 casos `200 image/*`** (PNG, SVG, JPEG), incluindo nomes com MAIÚSCULAS e com PONTO FINAL |
| **8. leitura do corpo** | distinguiu `host not allowed` / `fetch failed` / `upstream error` em todos os casos |

**O validador declarou o que NÃO conseguiu medir:** o rebinding **real** de duas respostas — porque
o `dns.lookup` do handler usa o resolver do sistema e não seguiu o servidor DNS de teste. Fica
**NÃO MEDIDO**, não «fechado por argumento».

`isBlockedIp` **não cobre as faixas de propósito especial** — e elas **passam a classificação**:

## 8. Lições desta geração

- **A pergunta certa não é «que caso me falta?» — é «onde é que eu decido e onde é que ele liga?».**
  Se não forem o **mesmo sítio**, nenhum filtro fecha nada.
- **Duas resoluções para a mesma pergunta são uma pergunta sem resposta.** O atacante escolhe a
  segunda.
- **Um pin vale mais que uma lista.** Classificar endereço a endereço é uma corrida que não se
  ganha; **devolver ao conector exactamente o que se validou** fecha a classe por construção.
- **O instrumento é parte do alvo.** Esta geração corrigiu **cinco** defeitos nos meus próprios
  instrumentos — incluindo o PoC que, ao replicar a cadeia antiga, era ele próprio o ponto cego.
- **Um mutante OBSOLETO é o mapa do próximo buraco.** M2/M7 deixaram de ser obsoletos no momento em
  que se lhes deu cobertura — e essa cobertura era a lacuna.
